# api-finder

用户描述他们想在 iSecure Center 平台上完成的集成任务，skill 搜索本地 `docs/` 目录中的 API 文档，返回匹配的 API 端点。

## 文档结构

所有 API 文档位于 `docs/` 目录下：

```
docs/
├── category.md              # 总目录 + 功能分类速查表
├── reference/
│   ├── 1_文档说明.md
│   ├── 2_开发前准备.md
│   ├── 3_协议概述.md
│   ├── 4_API概览.md          # 各服务的能力概览
│   ├── 5_编程引导.md          # 按业务场景编排的编程引导（关键参考）
│   ├── 资源目录/               # 6个文件：区域、资源、设备网管、人员/照片、组织、卡片
│   ├── 视频业务/               # 5个文件：视频网管、视频资源、视频功能、电视墙、视频参数配置
│   ├── 人脸应用接口/           # 3个文件：人脸应用、人脸资源、人脸管理
│   ├── 一卡通应用服务/         # 18个文件：访客、权限配置/下载/条目、食堂消费、门禁、梯控、可视对讲
│   ├── 车辆管控/               # 6个文件：车辆车库、停车场功能、园区卡口、行车监控、停车场网管、升降柱
│   ├── 报警检测/               # 6个文件：入侵报警(功能/资源)、动环监控、消防(功能/网管)、紧急报警
│   ├── 其他/                   # 3个文件：测温应用、事件服务、封闭区域人车管控
│   ├── 事件监听/               # 9个事件文件 + README
│   └── 附录/                   # 9个附录文件(A-I)
```

## 搜索策略

### Pass 1 -- 意图识别与模块匹配

1. 首先读取 `docs/category.md`，重点关注 **"五、接口功能分类速查"** 表格，该表将功能领域映射到具体模块：

   | 功能领域 | 关键词 | 匹配模块 |
   |----------|--------|----------|
   | 人员管理 | 添加人员、删除人员、修改人员、人员查询、人脸照片 | 资源目录/4、人员及照片接口.md<br>资源目录/6、人员卡片接口.md |
   | 视频监控 | 实时预览、视频流、回放、云台控制、PTZ、录像 | 视频业务/1-5 |
   | 门禁控制 | 开门、关门、常开、常闭、门禁点、门禁事件 | 一卡通应用服务/10、门禁功能接口.md<br>一卡通应用服务/11、门禁资源接口.md<br>一卡通应用服务/12、门禁网管接口.md |
   | 人脸识别 | 人脸录入、人脸比对、人脸识别计划、人脸分组 | 人脸应用接口/1-3 |
   | 访客管理 | 访客预约、访客登记、访客签离、访客黑名单 | 一卡通应用服务/1、访客功能接口.md |
   | 停车场 | 车辆管理、停车缴费、道闸控制、车位预约 | 车辆管控/1-6 |
   | 报警 | 入侵报警、消防、动环监控、紧急报警 | 报警检测/1-6 |
   | 梯控 | 电梯控制、梯控事件、梯控权限 | 一卡通应用服务/13-15 |
   | 可视对讲 | 对讲设备、出入事件 | 一卡通应用服务/16-18 |
   | 组织管理 | 添加组织、删除组织、修改组织、组织查询 | 资源目录/5、组织信息接口.md |
   | 区域管理 | 添加区域、修改区域、区域查询 | 资源目录/1、区域信息接口.md |
   | 权限下发 | 权限配置、权限下载、下载任务 | 一卡通应用服务/2-7 |
   | 消费 | 食堂消费、账户充值、消费记录 | 一卡通应用服务/8-9 |
   | 事件订阅 | 事件监听、MQTT订阅、事件回调 | 其他/2、事件服务接口.md<br>事件监听/ |
   | 测温 | 测温记录、测温分组、测温点 | 其他/1、测温应用.md |
   | 电视墙 | 上墙、下墙、场景切换 | 视频业务/4、电视墙.md |
   | 基础资源 | 区域、资源、设备网管 | 资源目录/1-3 |

2. 同时查看 `docs/reference/4_API概览.md`，了解各服务领域的能力范围，确认所选模块是否覆盖用户需求。

3. 同时查看 `docs/reference/5_编程引导.md`，该文件按业务场景（如"人员卡片维护流程"、"视频取流"、"云台控制"、"访客预约"等）编排，直接列出了实现每个场景需要调用的 API 名称（用【】标出）。如果用户描述的场景在编程引导中有对应章节，可以直接提取 API 名称。

### Pass 2 -- 精确端点匹配

根据 Pass 1 匹配到的模块文件路径，读取对应的 `.md` 文件：

1. **搜索方式**: 在目标文件中搜索与用户意图匹配的 API 标题（`####` 或 `#####` 级别标题）和接口说明
2. **关键匹配点**:
   - API 标题名称（如"批量添加人员"、"获取监控点预览取流URL"）
   - 接口说明中的功能描述
   - 每个 API 都包含：接口说明、接口地址、请求方法(POST)、请求参数、返回参数、请求/返回 JSON 示例
3. **交叉验证**: 将 5_编程引导.md 中提到的 API 名称与模块文件中的实际 API 端点进行交叉对比，确保准确

## 输出格式

对于每个匹配到的 API 端点，按以下格式输出：

```
### {序号}. {API名称}

- **接口说明**: {简要功能描述}
- **接口地址**: `{endpoint}`
- **请求方法**: POST
- **关键请求参数**:
  | 参数名 | 类型 | 必填 | 说明 |
  |--------|------|------|------|
  | {param} | {type} | {Y/N} | {desc} |

- **请求示例**:
  ```json
  {request JSON}
  ```

- **返回示例**:
  ```json
  {response JSON}
  ```
```

## 注意事项

- 所有 API 接口均使用 **POST** 方法，数据格式为 **application/json**
- 优先参考 `5_编程引导.md`，它能直接给出业务场景对应的 API 调用链
- 如果用户的问题涉及"事件"（实时推送），同时检查 `docs/reference/事件监听/` 和 `docs/reference/其他/2、事件服务接口.md`
- 如果找不到精确匹配，可参考 `4_API概览.md` 中的能力描述，向用户建议最接近的 API 模块
- 接口文档中所有路径基于 `docs/` 目录
