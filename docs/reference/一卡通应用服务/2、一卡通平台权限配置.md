##### 添加权限配置

**接口说明**

> 权限配置支持按组织、人员和设备通道配置权限，适用综合大楼、学校、医院等场景。<br>说明：权限配置数据采用异步分批入库方式，接口调用成功后返回权限配置单编号，在配置的过程中分批插入数据，只有当配置单结束时才能查询到完整的权限配置信息。相同的配置数据重复配置时，第一次配置生效后，后面相同的配置将自动过滤丢弃。<br>合作方配置的tagId用于让多个应用共用出入控制权限服务时，用以区分各自的配置信息。<br>注意点：不同业务组件设备通道隔离，应该根据业务场景使用不同的设备通道配置权限；如对相同的设备通道都有业务应用，那么人员隔离，应该根据场景使用不同的人员，否则会造成权限条目归属相互竞争的情况，在权限条目综合查询时，数据归属以最后一次入库配置为准。<br>单次接口最多支持1000个设备资源和1000个人员数据。

**接口版本**

> v1

**接口适配产品版本**

> 综合安防管理平台iSecure Center V1.3及以上版本

**接口地址**

> /api/acps/v1/auth_config/add

**请求方法**

> POST

**数据提交方式**

> application/json

**请求参数**

| 参数名称  | 参数位置  | 数据类型  | 是否必须 | 参数描述                                     |
| --------------- | --------- | --------- | ---- | ---------------------------------------- |
| personDatas | body | object[] | true | 人员数据列表 |
| +indexCodes | Body | string[] | true | 该参数和personDataType组合使用,<br>当personDataType传入组织时,indexCodes传入的是组织ID，[获取组织列表](/docs/软件产品-综合安防管理平台-API列表-资源目录-人员信息接口-组织信息接口#eea0304a)接口获取返回报文中的orgIndexCode字段；<br>当personDataType传入人员时,indexCodes传入的是人员ID，[获取人员列表v2](/docs/软件产品-综合安防管理平台-API列表-资源目录-人员信息接口-人员及照片接口#aa136eca)接口获取返回报文中的personId字段；最大1000条 |
| +personDataType | Body | string | true | 人员数据类型，<br>person人员，<br>org组织 |
| resourceInfos | body | object[] | false | 设备通道对象列表，最大1000条 |
| +resourceIndexCode | Body | string | true | 资源的唯一标识，资源为设备，[查询资源列表v2](/docs/软件产品-综合安防管理平台-API列表-资源目录-资源信息接口#da53ed76)接口获取返回报文中的indexCode字段； |
| +resourceType | Body | string | true | 资源类型，详见[附录A.50 设备通道类型](/docs/软件产品-综合安防管理平台-附录-附录A 数据字典#d98f04ce) |
| +channelNos | Body | number[] | false | 通道号 |
| startTime | body | string | false | 开始日期，开始与结束日期要么都为空要么都不为空。配置人员权限的有效期，为空时默认长期有效。采用ISO8601时间格式，最大长度32个字符，如2018-09-03T17:30:08+08:00 |
| endTime | body | string | false | 结束日期，开始与结束日期要么都为空要么都不为空。配置人员权限的有效期，为空时默认长期有效。采用ISO8601时间格式，最大长度32个字符，如2018-09-03T17:30:08+08:00 |

**请求参数举例**

```json
{
    "personDatas": [
        {
            "indexCodes": [

            ],
            "personDataType": "person"
        }
    ],
    "resourceInfos": [
        {
            "resourceIndexCode": "0a869b06f4ff4da29949acf006405c39",
            "resourceType": "acsDevice",
            "channelNos": [
                1
            ]
        }
    ],
    "startTime": "2018-09-03T17:30:08+08:00",
    "endTime": "2018-09-06T17:30:08+08:00"

```

**返回参数**

| 参数名称  | 参数位置  | 数据类型  | 是否必须 | 参数描述                                     |
| --------------- | --------- | --------- | ---- | ---------------------------------------- |
| code | body | string | false | 返回码，0 – 成功，其他- 失败，参考[附录E.2.3 出入控制权限错误码](/docs/软件产品-综合安防管理平台-附录-附录E 返回码说明-返回码说明#c3be41a7) |
| msg | body | string | false | 返回描述 |
| data | body | object | false | 返回数据 |
| +taskId | body | string | false | 配置单编号 |

    "msg": "success",
    "data": {

##### 人员权限使用状态设置

**接口说明**

> 设置人员权限的使用状态，默认人员权限使用状态为有效，当设置其他状态后可通过设置权限有效状态恢复。<br>说明：针对智能锁设备，人员权限状态的禁用和有效对应智能锁的冻结解冻功能。<br>按权限条目（人员与设备通道）设置可以通过权限条目综合查询章节接口可获取人员的权限使用状态。<br>按人员全局设置可以通过查询人员权限全局状态设置接口获取人员列表

**接口版本**

> v1

**接口适配产品版本**

> 综合安防管理平台iSecure Center V1.5.0及以上版本

**接口地址**

> /api/acps/v1/authConfig/personAuth/useStatus/configuration

**请求方法**

> POST

**数据提交方式**

> application/json

**请求参数**

| 参数名称  | 参数位置  | 数据类型  | 是否必须 | 参数描述                                     |
| --------------- | --------- | --------- | ---- | ---------------------------------------- |
| personIds | body | string[] | true | 人员ID列表，[查询人员列表v2](/docs/软件产品-综合安防管理平台-API列表-资源目录-人员信息接口-人员及照片接口#dd9d9d0b)接口获取返回报文中的personId字段 |
| useStatus | body | integer | true | 权限使用状态,<br>0-权限有效，<br>1-权限禁用 |
| resourceInfos | body | object[] | false | 资源设备对象列表，当为空时，表示人员权限全局设置 |
| +resourceIndexCode | Body | string | false | 资源的唯一标识，资源为设备，[查询资源列表v2](/docs/软件产品-综合安防管理平台-API列表-资源目录-资源信息接口#da53ed76)接口获取返回报文中的personId字段 |
| +resourceType | Body | string | false | 资源类型，详见[附录A.50 设备通道类型](/docs/软件产品-综合安防管理平台-附录-附录A 数据字典#d98f04ce) |
| +channelNos | Body | number[] | false | 资源通道号 |

**请求参数举例**

```json
{
    "personIds": [
        "37835310-f786-451a-8eb5-5d6c43b827cc"
    ],
    "useStatus": 1
}
```

**返回参数**

| 参数名称  | 参数位置  | 数据类型  | 是否必须 | 参数描述                                     |
| --------------- | --------- | --------- | ---- | ---------------------------------------- |
| code | body | string | false | 返回码，0 – 成功，其他- 失败，参考[附录E.2.3 出入控制权限错误码](/docs/软件产品-综合安防管理平台-附录-附录E 返回码说明-返回码说明#c3be41a7) |
| msg | body | string | false | 返回描述 |
| data | body | string | false | 无返回结果 |

**返回参数举例**

```json
{
    "code": "0",
    "msg": "success"
}
```

##### 按人员设置人员权限扩展参数

**接口说明**

> 权限配置支持按人人员和设备通道配置权限，适用人员权限有特殊参数需要下发的场景。说明：权限配置数据采用异步分批入库方式，接口调用成功后返回权限配置单编号，可通过《查询权限配置进度》，在配置的过程中分批插入数据，只有当配置单结束时才能查询到完整的权限配置信息。<br>权限配置的预计时间：每10万配置数据大概30秒。（配置数据量：人员数据量*设备数据量）。<br>1、 相同的配置数据重复配置时，第一次配置生效后，后面相同的配置将自动过滤丢弃。<br>2、 在相同人员和设备通道多次配置时，权限有效期和计划模板信息以最后一次配置为准（比如：先对人员分组A与设备分组D1，D2配置了计划模板T1，有效期为day1的权限，再对人员分组A，B与设备分组D1配置计划模板t2，有效期为day2的权限，那么人员分组A与设备分组D1存在重复配置情况，最终人员分组A与设备分组D1的计划模板为t2，有效期为day2）；<br>3、 人员扩展参数变更后，相同的参数以最后一次为准，不同的参数会和以前的参数合并，第一次需要传入人员扩展参数初始化值，供权限删除时，设置设备上为初始化值。<br>4、 tagId用于让多个应用共用出入控制权限服务时，用以区分各自的配置信息。建议使用组件标识。注意点：不同业务组件设备通道隔离，应该根据业务场景使用不同的设备通道配置权限；如对相同的设备通道都有业务应用，那么人员隔离，应该根据场景使用不同的人员，否则会造成权限条目归属相互竞争的情况，在权限条目综合查询时，数据归属以最后一次入库配置为准。
