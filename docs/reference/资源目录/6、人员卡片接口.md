##### 批量开卡

**接口说明**

> 该接口主要是应用于对多个人同时开卡的场景，输入卡片开始有效日期、卡片截止有效日期以及对应的人员、卡片关联列表，实现对多个人员同时开卡的功能，开卡成功后，可以到相应子系统开启卡片的权限，例如到门禁子系统开启人员门禁权限。

**接口版本**

> v1

**接口适配产品版本**

> 综合安防管理平台iSecure Center V1.5及以上版本

**接口地址**

> /api/cis/v1/card/bindings

**请求方法**

> POST

**数据提交方式**

> application/json

**请求参数**

| 参数名称 | 参数位置 | 数据类型 | 是否必须 | 参数描述                                     |
| --------------- | --------- | --------- | ---- | ---------------------------------------- |
| startDate | body | string | false | 卡片开始有效时间，时间格式：yyyy-MM-dd |
| endDate | body | string | false | 卡片截止有效时间,时间格式：yyyy-MM-dd<br>不能大于2037年12月31日 |
| cardList | body | object[] | true | 待开卡列表,最大支持50张卡，为空返回公共错误码，超过范围返回业务错误码，参考[附录E.other.3 卡片错误码](/docs/软件产品-综合安防管理平台-附录-附录E 返回码说明-返回码说明#b3555ef8) |
| +cardNo | Body | string | true | 卡号，最大长度64，建议是由读卡器直接读出来的，如果是三方系统同步过来，需要提前调研卡号的规则所购买的设备上是否兼容 |
| +personId | Body | string | true | 人员唯一标示， 根据[获取人员列表v2](/docs/软件产品-综合安防管理平台-API列表-资源目录-人员信息接口-人员及照片接口#aa136eca)接口获取返回参数personId |
| +orgIndexCode | Body | string | false | 人员所属组织IndexCode，不传默认使用根组织 |
| +cardType | Body | number | false | 卡片类型,1：IC卡；2：CPU卡；3：远距离卡；4：M1卡，默认1-IC卡 |

**请求参数举例**
```json
{
    "startDate": "2018-10-30",
    "endDate": "2018-10-30",

        {
            "cardNo": "100000001",
```
